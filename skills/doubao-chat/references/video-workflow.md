# 豆包视频制作流程

用于用户通过已登录豆包网页规划、评估、生成或续接视频。按当前任务读取相关部分；具体工具参数与网页适配见 [媒体操作说明](media-tools.md)。

## 1. 明确当前任务与制作范围

从当前对话、已有项目和用户选择中取得：交付用途、总片长或片段范围、画幅、人物与画风、声音和文字要求、生成次数或费用上限。沿用已有授权，只有缺失信息会改变执行范围时才询问。

- 用户只要求调研、评估或整理方案时，使用已有素材、文档与必要的只读网页检查；不要自行提交生成
- 用户要求修改技能或桥接时，修改授权范围内的文件；验证修改不自动授权消耗视频次数
- 用户已授权制作时，完成范围内的准备、上传、生成、下载和剪辑，无需逐步重新请示
- 模型、免费时长、可传图片数量和可用控件以当前账号界面为准。网页滑块的最大值、模型官方接口能力、提示词中的参数都不等同于该账号可免费使用的能力
- 为片段和必要的返工安排次数，数量依据叙事和实际限额；不为了用完免费次数而补时长。新增试片也计入授权范围，不额外消耗一次未包含的测试

免费任务遇到额度耗尽或付费要求即停止，不开通会员。用户明确选用已开通的付费额度时，按其授权预算核验和使用；本机桥接不自动购买服务或点击支付控件。

将用户报告的剩余次数与网页核验值分别记录，并注明来源与时间。无法看到余额时明确“用户说明，未独立核验”，不根据提示词或计划次数宣称余额真实可用。

## 2. 先确定画面，再生成动作

对固定角色、多片段或需要连续性的作品，优先准备清晰的角色、场景和分镜图片。已有合格素材可直接复用，不为满足流程重新生成。

| 图片用途 | 应明确的内容 |
| --- | --- |
| 角色参考 | 哪位角色、外观与服装；单人出场优先使用单人图，多人参考必须明确主体 |
| 场景参考 | 镜头位置、背景、主要道具及其位置、光线和色调 |
| 分镜或关键画面 | 当前镜头的主体姿态、动作起点与必要的结束状态 |
| 已生成尾帧 | 仅在检查合格后，用于同一场景的动作与构图接续 |

只上传当前片段需要的素材。对简单动作，通常一张完整分镜图足够；起止状态有必要明确时，可增加结束画面。需要多图时逐张写清用途和先后关系，不把整条视频全部图片无差别塞入每个片段。

先查看实际图片：人物比例、脸与服装、光线与肤色是否符合设计，手与物体是否接触正确，道具是否缺失或多出，画幅是否匹配，是否包含不打算继承的文字或视觉效果。跨分镜还要比较同一人物与场景的位置和样貌。

素材有问题时，回到已定稿角色或场景准备正确的分镜；仅当图片制作或编辑在用户授权范围内时执行相应操作，否则列出所需调整。不要依赖“忽略这块阴影”等文字消除图片里已经存在的明显缺陷。

## 3. 根据图片用途组织提示词

提示词按“图片对应关系 → 主要动作 → 镜头与场景约束 → 声音和文字要求”组织。动作和道具必须支持内容表达；用可见动作描述替代“展示现金流”等抽象要求。

- 多图普通参考说明哪张用于人物、哪张用于构图、哪些画面按顺序出现。保持图片内容与文字要求一致
- 简单知识动画可优先采用一个主要动作和少量自然表情。动作需要多个道具、换景或明显姿态变化时，增加对应分镜或合理切镜，不把复杂动作压成连续长镜头
- 新增道具要先明确它从哪里来、放在哪里、如何拿取以及有什么叙事用途；未定义的白盒子或空白纸片容易变成无意义物体
- 风格和照明依照当前项目选择；例如平面卡通不需要的手机彩色反光，不应在动作描述中主动引入。人物需要自然闭嘴时，以眼神、眉毛和手部动作表达情绪
- 有声、静音、字幕或口型由任务决定。只有交付纯画面素材、后期统一配音与字幕时才要求无声和无叙事文字，不能作为所有视频的默认禁令
- “无声”“无字幕”等仍是生成要求，不能当作已生效的工具参数或结果保证。以下载后实际检查为准，保留平台正常AI标识

可按需要参考以下提示词结构，填入当前任务事实；它不是固定参数或每次必用的模板：

> 图片1用于确定当前镜头的人物、构图、道具和光线；图片2是同一镜头需要到达的结束姿态，画面按图片1到图片2的顺序发展。人物缓慢完成一个明确动作，镜头保持指定位置。现有道具保持原位。声音与画面文字按本次交付要求处理。

删除不适用的部分，不反复堆叠相同禁令。不要对模型无法保证的逐秒动作和严格画面匹配作承诺。

## 4. 区分普通参考、首帧与首尾帧

| 方式 | 可以据实表述的控制程度 |
| --- | --- |
| 普通参考图或多图参考 | 引导主体、画风、构图和顺序；不能声称像素一致或严格锁帧 |
| 网页明确的首帧入口 | 只有页面控件与桥接角色核验通过后，才表述使用了首帧模式 |
| 明确的首尾帧模式 | 同时需要实际网页入口和调用能力；不能用两张普通附件代替严格首尾帧 |

本机桥接当前 imageRole 只有 reference 与 first_frame。first_frame 需要实际找到标为“首帧/起始帧”的输入，并核验 roleVerified；尚无 last_frame 参数。不要根据模型API文档推断豆包网页支持相同控制，更不要构造未实现的参数。

普通参考模式可以要求按两张图的顺序生成，但必须在说明中保持“参考”性质。当前能力不足时，可以使用已授权的普通参考和剪辑切镜完成任务；用户明确要求严格锁帧时，先说明能力缺口，不能悄悄降级后宣称实现。

## 5. 固定网页对话并确认真实上传

新建或绑定当前任务的固定 sessionId、tabId 与对话URL。用户另行操作豆包时，仍使用这个固定对话；页面URL变化或 conversation_mismatch 时暂停当前提交，先确定正确对话。

用 inspect 检查真实上传入口、参数控件、编辑器、草稿和附件。选择器来自当前页面，不复用未检查的旧控件。编辑器有用户草稿或来源不明的附件时，不覆盖或直接提交。

上传后核对图片数量、文件名、顺序和真实解码预览。loaded_preview / existing_loaded_preview 是上传确认；仅有路径文字、界面图标或占位图不算上传成功。有多张图但无法确认顺序时，先解决对应关系再生成。

后台标签页可能隐藏编辑器或禁用发送。只在实际检查发现这种情况时，请用户将固定任务页置于前台；不要通过其他活跃对话发送，也不要用调试协议或读取登录数据绕过正常网页操作。

生成前确认当前模型、时长和比例是否已通过实际控件设置。parameterControl=prompt_only 时说明仍是文字要求，后续核对真实结果。当前界面或登录恢复的问题按 SKILL.md 连接恢复流程处理。

## 6. 记录尝试，避免重复生成

每个有意发起的片段尝试使用稳定且唯一的 idempotencyKey；记录对应 sessionId、对话URL、jobId、图片用途与顺序、实际提示词、网页参数和状态。保留原任务状态，不用后来的失败返工覆盖已成功素材的来源。

| 观察到的状态 | 下一步 |
| --- | --- |
| 明确尚未提交 | 修复上传或控件问题，在原授权内使用同一次尝试继续；仍先确认没有真实新任务 |
| 已提交或 unknown | 查询原 jobId、同一 key 对应任务和固定对话，不更换 key 再发一次 |
| 网页明确请求参数确认 | 核对尚无新视频及确认未发送，按已有授权完成一次确认；不把等待回复当作请求重复提交 |
| 只有“稍后发送”或“已生成”的文字 | 查真实视频元素；有封面时检查并打开实际播放器 |
| 已有真实生成视频 | 必要时 adopt 登记、下载，不重新生成；采用时排除旧片来源，确认对应当前尝试 |
| 下载未完成 | 查询同一 jobId 的下载状态，不重新生成视频 |
| 结果明确不合格 | 记录问题，只有授权包含返工且额度允许时，才用新 key 有意重做 |
| 当前授权额度耗尽，或出现范围外付费要求 | 立即停止新生成与自动重试；保存素材和拒绝证据，报告缺镜及未完成范围 |

分别记录提交请求数、实际生成成功数和观察到的额度扣减，不将失败请求或用户估计直接当作实际计费。每日额度恢复后，先重新核验当前账号状态和仍有效的任务范围，再继续未完成部分；不假定到次日便必然恢复。

## 7. 验收原片，再决定是否续接

下载成功后核对本地文件、真实时长、画幅、视频和音频流。按素材用途查看关键帧或每秒抽帧；需要精确连续动作时进一步查看衔接处的短片。完整解码只能验证文件可读，不能替代视觉判断。

- 人物与场景：外观和服装一致，光影及肤色符合设计，无多余角色、肢体或无理由换景
- 动作与道具：手和物体接触合理，物体没有突然出现、消失、变形或改变数量；文字要求的动作确实出现
- 声音与文字：检查实际音轨及可见字幕、口型是否符合交付要求；抽帧检查要说明范围，不声称覆盖全部帧
- 衔接：前段结束与后段开始的姿态、构图、颜色和道具是否匹配，是否需要正常切镜或局部剪辑

用 tail 提取后，还要查看实际尾帧。提取成功不等于参考图合格；闭嘴、肤色、道具位置或其他设计已出错时，不继续传播该尾帧。按授权准备经过修正的参考图，或从已定稿分镜切入下一镜头。

如需改用较早的合格帧，应重新检查并记录源片与时间点；后期将前片结束位置与该帧对齐。普通参考依然不能保证无缝接续，不承诺连续画面绝对不跳变。

## 8. 组装与交付

保存原片与生成来源，按叙事需要剪辑。声音、字幕、金额和日期依照任务选择由后期准确制作；不依赖模型自动生成的文字替代需要精确展示的信息。原音轨不合适时按制作要求移除或替换，并保留原始素材。

成片核对实际音画时长、字幕和金额位置、重要内容是否缺失，以及首尾和切镜是否可用；对最终文件进行适当的解码检查。不得通过删除正常平台标识包装来源。

原计划缺镜或待返工时，只在用户允许或任务可接受的范围内交付明确标注的剪辑草稿，说明替代方案、缺镜、视觉问题和已完成内容。被用户否定的素材不能用于填补缺镜。常规剪辑与适度变速可按叙事需要采用；不得用循环、静态替代或过度慢放凑时长并宣称原计划完成。

当前项目按需要保存：脚本和分镜、参考图片及用途、请求与任务记录、原片及尾帧、验收观察、剪辑时间轴与成片。保留已有项目结构，不要求所有任务新建相同目录。草稿与定稿使用能区分的名称，并提供实际可播放的文件。
